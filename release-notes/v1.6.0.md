dbwarp-blueprint 1.6.0 release binaries.

Release highlights:
- Blueprint schema v7 adds explicit table classification, storage,
  partitioning and segment state; richer column semantics; and per-object and
  capture-wide evidence for structure, row counts, allocated bytes and
  statistics.
- Missing, denied, malformed and selection-limited evidence remains visible.
  It cannot silently become a measured zero or a complete inventory.
- PostgreSQL, MySQL and SQL Server retain bounded row and byte sampling with
  clearer provenance for complete reads, partial samples, catalog estimates,
  row-security boundaries and adaptive retries.
- Artifact inventories now carry catalog-backed per-object requirement status
  and bounded complexity evidence. Aggregate completeness fails closed when
  the selected assessment population cannot be proved complete.
- Decks now include a non-table objects slide and, when complexity was
  captured, a separate artifact complexity slide with coverage beside every
  band.
- SQL Server memory-optimized tables are represented without treating
  unmeasured memory storage as ordinary disk data. External-table coverage is
  reported as unavailable when PolyBase is not present.
- The SQL Server, PostgreSQL, Parquet and Windows authentication dependency
  stacks are updated to releases that fix published security advisories.
- Linux release archives include SQL Server Kerberos/GSSAPI authentication and
  load the platform runtime only when integrated authentication is selected.
  Windows release binaries continue to include SQL Server SSPI authentication.
  Both integrated modes use the operating-system credential and can fail closed
  on an unexpected server principal.
- The SQL Server enhanced grant scripts now add one server-level permission
  in a separate batch: VIEW SERVER STATE on 2019, VIEW SERVER PERFORMANCE
  STATE on 2022 and 2025. It lets an enhanced capture with --artifact-detail
  graph or analyzed report coarse CPU and memory bands for a self-managed
  server. Basic and standard do not grant it and report those bands as unknown;
  a DBA can remove the batch to keep enhanced without it.
- Schema-v1 through schema-v6 Blueprint files remain readable. Older tools
  may reject schema-v7 output, so update and validate every tool that reads a
  Blueprint before using the new format.

Support boundary:
- Supported databases are PostgreSQL 13-18, MySQL 8.0/8.4/9.7 and SQL Server
  2019/2022/2025, with Oracle Basic catalogue capture for Oracle 12c, 19c, 21c
  and 23ai/26ai supported as a preview. See `sql/grants/ORACLE_PREVIEW.md`.
- Known Oracle preview limitation on 21c: the DBA capture scripts can fail
  with ORA-03106 or ORA-03120 when SQL*Plus clients of different major
  versions run them against the same 21c database while the earlier run's
  statements are still cached. Use one SQL*Plus major version per database,
  or have the DBA flush the shared pool before changing client version.

Trust and operation:
- The binary sends no telemetry and does not upload the Blueprint.
- Live modes connect only to the configured database endpoint and identity
  services described in AUDIT.md. Local Blueprint, deck, Parquet, Avro and
  bundle operations initiate no database connection.
- Verify the downloaded archive and the extracted executable against the
  checksums from this exact release before running it.
- English documentation is authoritative. Machine-translated documents are
  supplemental; review the translation notice before relying on one.
