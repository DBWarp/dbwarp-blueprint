**言語:** [English](../../SECURITY.md) | [Deutsch](../de/SECURITY.md) | [Français](../fr/SECURITY.md) | [Español](../es/SECURITY.md) | [Polski](../pl/SECURITY.md) | **日本語** | [简体中文](../zh/SECURITY.md)

`dbwarp-blueprint` には、ライブデータベース、構造化ファイル、バッチ、
バンドル、デッキの各モードがあります。選択したモードによってネットワークと
ファイルシステムの範囲が決まります。テレメトリ、更新確認、ライセンス確認、
分析呼び出し、アップロード経路はありません。

このページでは、チームが実行可否を判断できるよう、セキュリティ境界を説明します。

## 脆弱性の報告

脆弱性の疑いは、
[GitHub の非公開脆弱性報告](https://github.com/DBWarp/dbwarp-blueprint/security/advisories/new)
を通じて非公開で報告してください。セキュリティ上機密の詳細を公開 issue に含めないでください。
正確なリリースバージョン、オペレーティングシステム、再現手順、報告の評価に必要な最小限の安全な根拠を含めてください。

## ネットワーク

| モード | 実行時のネットワーク使用 |
|---|---|
| PostgreSQL、MySQL、または SQL Server のライブ `--connect` データベース接続 | 指定されたデータベースエンドポイントへのデータベースドライバーセッションを 1 つ確立します。DNS 名前解決では、構成済みのリゾルバーに接続する場合があります。統合 Kerberos/SSPI 認証では、KDC やドメインコントローラーなど、構成済みの ID 基盤にも接続する場合があります。 |
| 明示的な確認が必要な Oracle プレビュー | オペレーターが選択した `--oracle-sqlplus` 実行ファイルだけを子プロセスとして起動し（利用可能な場合は制限付きの `-V` プローブを含む）、カタログセッションに使用します。認証情報は標準入力で送信され、プロセス引数には配置されません。子プロセスは空のプライベートディレクトリを `TNS_ADMIN` として受け取ります。環境は消去され、存在する場合に限り `PATH`、`SystemRoot`、`WINDIR`、`ORACLE_HOME`、`LD_LIBRARY_PATH`、`DYLD_LIBRARY_PATH`、`LIBPATH`、`SHLIB_PATH` が転送されます。固定のロケール、タイムゾーン、およびプライベートな `TNS_ADMIN` 値は別途設定されます。 |
| `--batch-manifest` | マニフェスト内のデータベースソースごとに 1 つのデータベースドライバーセッションを順次処理します。ローカルの Parquet および Avro ソースはネットワークを使用しません。上記の DNS と統合認証に関する条件は引き続き適用されます。 |
| `--from-toml`, `--from-parquet`, `--from-avro`, `--bundle-list`, `--bundle-extract`, `--bundle-pack` | アプリケーションが開始するネットワーク接続はありません。ネットワークマウントされたファイルシステム上の入力は、引き続きオペレーティングシステムまたはストレージ側の考慮事項です。 |

本ツールは DBWarp サービスやクラウド API を呼び出しません。データベース
ドライバーとホストのオペレーティングシステムは、上記のプロトコル補助通信を
行い、システムのトラストストア、DNS 設定、動的ライブラリ、統合認証の設定や
資格情報キャッシュを参照する場合があります。

`--max-wall-secs` は 2 つの独立した保護を設定します。PostgreSQL はセッションローカルの
`statement_timeout` を、MySQL はコレクターの読み取り専用 `SELECT` にセッションローカルの
`max_execution_time` を使用します。SQL Server には文全体の経過時間に対応するセッション設定がないため、
コレクターはセッションローカルの `LOCK_TIMEOUT` でロック待機を制限し、その他の停止にはクライアント側の期限を維持します。
クライアント側の期限が切れた場合、ツールは接続を切断しますが、SQL Server がサーバー側のキャンセルを確認したとは主張しません。
再試行する前に、サーバーの処理が停止したことを確認してください。

## 読み取るファイル

実行時に、アプリケーションが直接読み取るのは、コマンドラインで選択した入力、または
バッチやバンドルの入力から参照される入力だけです:

| ファイル | 読み取る時点 |
|---|---|
| `--user-file` | ユーザー名のソース |
| `--password-file` | パスワードのソース |
| `--anonymization-key-file` | オプションのHMACキー。このキーは、バイナリまたはSQLフォールバック正規化器が、承認された実行間で匿名オブジェクトラベルを維持するために使用されます。モードは、Unix上でgroup/otherの読み取りを防止する必要があります。 |
| `--azure-token-file` | SQL Server Entra ID トークンのソース |
| `--tls-ca` | 信頼する CA バンドル |
| `--tls-cert` | クライアント TLS 証明書 |
| `--tls-key` | クライアント TLS 秘密鍵 |
| `--from-toml` | オフラインでデッキを構築するための既存の dbwarp-blueprint TOML ファイル |
| `--from-parquet` | Parquet ファイルのメタデータと、明示的にサンプリングへ同意した場合は上限付きのデコード済み行 |
| `--from-avro` | Avro オブジェクトコンテナーのメタデータとレコード。レコード数を数えるには Avro 全体を走査する必要があります |
| `--batch-manifest` | バッチマニフェスト、およびそれが参照するすべてのローカル構造化ファイル、資格情報ファイル、トークンファイル、TLS ファイル |
| `--bundle-list`, `--bundle-extract`, `--bundle-pack` | バンドル TOML と、選択した操作に必要な相対パスの Blueprint ファイル |
| 制御端末またはコンソール | 対話式パスワード入力（Unix 系システムでは `/dev/tty`） |

アプリケーションには、`~/.pgpass`、`~/.my.cnf`、クラウド資格情報ファイル、SSH 鍵、シェル履歴、既定のデータベースパスワード環境変数を読む明示的なフォールバックはありません。プラットフォームのデータベース、TLS、DNS、ID ライブラリは、独自のシステム設定や資格情報キャッシュを参照する場合があります。ポリシーでプロセスとライブラリの完全なインベントリが必要な場合は、OS レベルのトレースを使用してください。

PostgreSQL と MySQL では、指定した `--tls-ca` PEM バンドルが組み込みの
Mozilla ルートを置き換えます。SQL Server は `--tls-ca` を省略すると
オペレーティングシステムのトラストストアを使用します。指定する `.pem` または
`.crt` ファイルには CA 証明書を正確に 1 つだけ含める必要があり、そのルートを
置き換えます。SQL Server は証明書を検証する両方のモードでホスト名を検証し、
ドライバーがクライアント証明書認証を実装していないため、
`--tls-cert`/`--tls-key` を `DBP1015E` で拒否します。

## 書き込むファイル

実行時に、本ツールは次を書き込む場合があります:

| ファイル | 書き込む時点 |
|---|---|
| `--out` | ライブデータベース、構造化ファイル、バンドル抽出、バンドル作成の各モードにおける Blueprint 出力 |
| `--deck` | 匿名化されたBlueprintまたは `--from-toml` 入力からローカルに生成される、任意の PowerPoint (.pptx) サマリー（追加のデータベース読み取り、ネットワーク、サードパーティライブラリは不要） |
| `--audit-log` | 監査ログの任意のコピー |
| `--out-dir` | `bundle.toml`、`blueprints/*.blueprint.toml`、`audits/*.audit.txt`、所有権マーカー、および 1 つ以上のソースが失敗した場合の `errors.txt` を含むバッチディレクトリ。アトミックな公開中は同階層のステージングディレクトリを使用し、処理済みの失敗時には削除します |

監査ログは stderr にも出力されます。

すべての監査ログとバッチの `errors.txt` は、アクセス制御された運用証跡として
扱ってください。エンドポイント名、ローカルパス、マニフェストのソース ID、
ドライバーエラー、タイミングデータが含まれる場合があります。SQL Server では、
監査に正確な認証ログイン (`ORIGINAL_LOGIN()`)、有効なサーバープリンシパル
(`SUSER_SNAME()`)、データベースプリンシパル (`USER_NAME()`) に加え、任意の
期待プリンシパルと検証結果が含まれます。これらの識別情報は単一ソースの
Blueprint やデッキには書き込まれません。バンドルメタデータには、オペレーターが
指定したソース ID、タグ、データセットグループ ID が保持されるため、匿名の値を
使用し、転送前にバンドル TOML を確認してください。

## 環境変数

既定では、実行時に資格情報用の環境変数を読み取りません。

`--password-env NAME`、`--user-env NAME`、または `--azure-token-env NAME` を渡した場合、本ツールはその名前の変数だけを読み取ります。`PGPASSWORD`、`MYSQL_PWD`、`MSSQL_PASSWORD` などの一般的な既定値にはフォールバックしません。

## 資格情報

資格情報は、意図的に `Debug`、`Display`、`Clone`、またはシリアライズを実装していない `Secret` 型でラップされます。これにより、誤ってログ出力するコードはコンパイルしにくくなります。

資格情報は、接続確立のためだけにデータベースドライバーへ渡されます。出力ファイルや監査ログには書き込まれません。監査ログには値ではなく、`file:/etc/dbwarp/db.pass` などの資格情報ソースが記録されます。

## ドライバーが所有する資格情報のコピー

ゼロ化の対象は DBWarp Blueprint が所有する `Secret` バッファです。データベースドライバー、TLS ライブラリ、OS 認証プロバイダー、アロケーターが作成したコピーの消去までは保証できません。現在の MySQL ドライバー API は所有された `String` を要求するため、`src/engine_mysql.rs` はパスワードを `Secret` から `OptsBuilder` へ明示的にコピーします。このコピーはゼロ化されず、builder/options が破棄されるまで残ります。PostgreSQL、SQL Server、プラットフォーム認証ライブラリも wrapper の外で内部コピーを作成する場合があります。機密性の高い資格情報を使用するホストでは、必要に応じてプロセス検査と swap を制限してください。

## 拒否される資格情報の形式

接続 URI に埋め込まれたパスワードは拒否されます。たとえば、次は受け付けられません:

```text
postgresql://user:password@host/db
```

代わりに `--password-file`、`--password-env`、または対話式プロンプトを使用してください。これは、シェル履歴、プロセス一覧、または端末のスクロールバックを介したパスワード漏えいを避けるためです。

## 出力の安全性

Blueprintファイルは、人が読んでレビューできるよう設計されています:

- 実際の識別子は `table-001` や `col-1` などのキー付き匿名名に置き換えられる
- 数値は各フィールドで文書化された正確または丸め済みの精度を使用し、正確な長さモードには明示的な同意が必要
- コメントは固定され、データチャネルとして使用されない
- 行の値は一切出力されない
- 圧縮サンプルは、有効化された場合にローカルで圧縮されて破棄される

ライブ Tier 2 では、投影されたサンプル値のペイロードをテーブルごとに最大 16 MiB に制限します。
非常に幅の広いテーブルでは要求行数を減らし、MySQL と SQL Server の適応的な再試行も含め、
エンジン固有のサーバー側切り詰めを通じて可変幅セルを投影します。
スタイルプローブには、その SQL 投影内で別途上限を設けます。
ローカルのプローブエンコーダーも、テーブルごとの上限を独立に適用します。

これはネットワーク通信量やプロセスメモリを 16 MiB に制限するものではありません。
プロトコルのフレーミング、別途返される元の長さのメタデータ、PostgreSQL のバイナリ値の
16 進表現、再試行、ドライバーバッファによって追加のオーバーヘッドが生じます。
非常に大きな値は、圧縮および値の要約測定に、上限付きの接頭辞だけが寄与する場合があります。
コレクターは、サンプリングした値の元の長さをサーバー上で別途取得し、返された接頭辞の長さだけでなく、
その元の長さに選択された長さ精度ポリシーを適用します。
サンプリングの来歴情報には該当する制約が記録されます。出力に上限があることは、
値全体を測定した証拠にはなりません。

テーブル、スキーマ、インデックス、および非テーブルオブジェクトの順序付けには、ドメイン区切りのHMAC-SHA256が使用されます。 既定では、このツールはオペレーティングシステムから新しいプロセスローカルキーを取得し、それを一切出力しません。これにより、オフラインの読み取り元が候補となるソース名を検証することを防ぎます。 `--anonymization-key-file`は、承認された比較実行間で同じ匿名ラベルを維持する必要がある場合にのみ使用してください。 ファイルには、正確に32バイトの生のデータ、または64文字の16進数データが含まれており、認証情報と同様に保護する必要があります。 監査ログには、一時的なキーが使用されたか、ユーザーが提供したキーが使用されたかが記録されますが、キーの実際の値は記録されません。

標準ライブラリだけで構成される SQL フォールバックの `blueprint_format.py` 正規化ツールも、同じキー付き順序契約を使用します。`--anonymization-key-file` がない場合は OS から新しいランダムキーを取得し、正規ヘッダーの後に生成元とキー取得元を示す固定コメントを追加するため、Rust コレクターの出力と混同できません。

正規化前の SQL フォールバック中間 JSON には、実際のスキーマ、テーブル、列、インデックス名が含まれます。MySQL の `COLUMN_TYPE` には宣言済み enum/set メンバーも含まれる場合があります。SQL スクリプトにはスキーマ部分選択機能がなく、アプリケーション監査ログも生成しません。中間 JSON を機密性のあるスキーマ素材としてソース環境内に保持し、ローカルで正規化して、レビュー済み TOML だけを転送してください。選択したスキーマだけが承認されている場合や、完全な監査、トポロジ、成果物、サンプリング証拠が必要な場合は Rust コレクターを使用してください。

これにより開示リスクは低減しますが、すべての出力があらゆる受信者にとって
安全になるわけではありません。匿名化されたスキーマ形状、依存関係グラフ、
エンジンバージョン、明示的に有効化した正確値のフィールド、特殊なサイズ分布から、
ワークロードを識別できる場合があります。共有する前に、組織のデータ分類
ポリシーに従って Blueprint とバンドルの出力をレビューしてください。監査や
`errors.txt` を匿名化済み Blueprint と同様に送信しないでください。

正確なフィールドについては、[`FORMAT.md`](FORMAT.md)を参照してください。

## 監査ログ

すべての実行で、次を列挙した監査ログが出力されます:

- 接続したデータベースエンドポイント
- 使用した資格情報ソース
- セッションから取得できる場合、SQL Server の認証プリンシパル、有効な
  サーバープリンシパル、データベースプリンシパル
- TLS モード
- 読み取ったファイル
- 書き込んだファイル
- 実行したクエリ
- 行サンプリングを有効にしたかどうか
- 最終結果

[`AUDIT.md`](AUDIT.md)を参照してください。

## ソースレビューの開始点

重点的にレビューする場合:

- `src/secret.rs`: 資格情報ラッパー
- `src/main.rs`: CLI、同意ゲート、監査出力
- `src/audit.rs`: 監査ログのレンダリング
- `src/format.rs`: 匿名化された出力形式
- `src/tls.rs`: TLS 設定
- `src/engine_pg.rs`、`src/engine_mysql.rs`、`src/engine_mssql.rs`: データベース固有のカタログリーダー
