# テーブル以外のアーティファクト・インベントリ

> **翻訳に関する注記:** これは機械支援翻訳であり、ネイティブの技術レビューが必要です。[正本の英語版](../ARTIFACT_INVENTORY.md)が優先され、この文書を契約文言として使用しないでください。

**言語:** [English](../ARTIFACT_INVENTORY.md) | [Deutsch](../de/ARTIFACT_INVENTORY.md) |
[Français](../fr/ARTIFACT_INVENTORY.md) | [Español](../es/ARTIFACT_INVENTORY.md) |
[Polski](../pl/ARTIFACT_INVENTORY.md) | **日本語** |
[简体中文](../zh/ARTIFACT_INVENTORY.md)

Blueprintsは、テーブル以外のデータベースオブジェクトやデプロイメントの前提条件を、ソース名、定義、エンドポイント文字列、シークレット、証明書、キー、またはバイナリを公開することなく記述できます。この情報により、DBWarpは移行の複雑さを推定し、パッケージ、インフラストラクチャ、セキュリティ承認、または支援が必要な作業を特定できます。

インベントリは機能に関する主張ではありません。オブジェクトが報告されたとしても、DBWarpがそれを自動的に再作成または変換できることを意味するものではありません。DBWarpに問い合わせて、サポートされているオブジェクトの種類を確認してください。

## 詳細レベル

`--artifact-detail` でプライバシーと計画情報のバランスを選択します。

| 値 | データベース読み取り | Blueprint 出力 | 同意 |
|---|---|---|---|
| `none` | インベントリ・カタログも定義も読まない（件数のみのトポロジプローブは引き続き実行） | v7 で未要求を明示するインベントリ。件数もグラフも出力しない | 追加同意なし |
| `summary` | カタログのみ。定義は読まない | 種類別および外部前提クラス別の件数 | 既定。追加同意なし |
| `graph` | カタログと依存メタデータ。定義は読まない | 件数、安定した匿名オブジェクト、依存エッジ | `--yes` が必要 |
| `analyzed` | カタログ、依存関係、利用可能な定義 | グラフと境界付き言語機能・複雑度バンド | `--yes` が必要 |

既定値は `summary` です。テーブル構造の収集は許可されても、テーブル以外の
カタログが禁止される場合は `none` を使用します。定義を読まずに依存関係を
計画する場合は `graph`、定義の一時読み取りが承認された場合だけ `analyzed` を
使用します。

```bash
./dbwarp-blueprint \
  --connect postgresql://blueprint_user@db.internal/appdb \
  --password-file /etc/dbwarp/blueprint.pass \
  --tls-mode verify-full \
  --tls-ca /etc/pki/internal-root.crt \
  --artifact-detail analyzed \
  --out appdb.blueprint.toml \
  --audit-log appdb.blueprint.audit.txt \
  --yes
```

## プライバシー契約

アーティファクト出力は、閉じた語彙による境界付きメタデータだけを含みます。

- `view-001`、`function-002`、`schema-A` のような実行内で一貫した匿名 ID。
  実行間の安定性には、同じ保護された `--anonymization-key-file` の再利用が必要です。
- 種類、サブタイプ、階層、可視性、セキュリティ・モードの閉じたトークン
- 匿名のアーティファクト ID またはテーブル ID だけで表す型付き関係と、閉じた証拠・未解決理由トークン
- 移行計画用の、境界付きでエンジン認定済みの機能要件
- 自由記述ではなく件数と境界付きバンド
- `pg_proc`、`information_schema.views`、`sys.objects` などの標準カタログ名
- 名前や実体を含まない外部前提クラス

ソース・オブジェクト名、SQL または手続き型ソース、スキーマ名、プリンシパル、
エンドポイント、プロバイダ、資格情報、鍵、証明書本文、Assembly ファイル、
拡張パッケージ名、ロード可能ライブラリ名は含みません。

`analyzed` モードでは、コメントとリテラルを除去して境界付き字句集計を作る間だけ
定義を保持します。解放時にゼロ化する所有者で管理し、シリアライズ、ログへの記録、
監査ログへの格納、他サービスへの送信は行いません。これはプロセス・メモリの露出を減らす制御であり、
OS のページングや特権デバッガを不可能にする保証ではありません。

匿名グラフでも件数とトポロジからアプリケーションを識別できる可能性があります。
そのため `graph` と `analyzed` は、`--yes` がなければ `DBP1014E` で失敗します。

## 完全性の証拠

`[artifact_inventory]` ブロックは自己監査可能です。

| フィールド | 意味 |
|---|---|
| `contract` | 独立してバージョン管理される契約。v7 は `dbwarp-blueprint-artifacts/v2`、旧 Blueprint スキーマは v1 を維持 |
| `detail` | 要求した詳細レベル |
| `scope` | v7 カタログ範囲: `all-visible-schemas`、`selected-schemas`、`structured-source`、`unknown` |
| `visibility` | `full`、`privilege_filtered`、`unknown` |
| `inventory_complete` | 完全な可視性があり、読めないカタログも未モデル化ファミリもない場合だけ true |
| `dependencies_complete` | 依存ソースを読め、モデル化対象を説明できる場合だけ true |
| `requirements_complete` | V7 集約値。エンジンのバージョンとエディションを確認し、選択範囲の評価対象が完全に網羅され、出力されたすべての成果物で `requirement_status = complete | not_applicable` の場合にのみ true。省略は false を意味する |
| `analysis_complete` | `analyzed` で、利用可能な全分析が完全な場合だけ true |
| `catalogs_read` | 正常に調査した標準カタログ・ファミリ |
| `catalogs_unreadable` | 失敗または利用不能だったカタログ・ファミリ。無関係なオブジェクト別要件証拠を消さず、影響する完全性を低下させる |
| `catalogs_not_applicable` | 適用不能と証明されたファミリ。読み取り済み・読み取り不能の集合と重ならない |
| `families_not_inventoried` | このリリースでインベントリされない既知のオブジェクト・ファミリ |

任意カタログの失敗でオブジェクトを黙って省略しません。実行は `DBP1410W` を出し、
対象カタログを記録し、対応する完全性を false にします。低権限アカウントでも、
不在を証明したように見せず、有用な部分インベントリを作成できます。

`object_count` は単一のネイティブカタログ行数ではなく、出力されたアーティファクト
レコード数です。Oracle のパッケージとオブジェクト型は仕様、本文、メンバーとして
モデル化され、本文が統合言語分析を持ちます。複数カタログで観測した同一オブジェクトは
1 回だけ数えます。トリガーのメタデータとソースは匿名化前にネイティブ ID で結合します。

## 集約複雑度契約

スキーマ v7 は `graph` と `analyzed` に集約専用の
`[artifact_inventory.complexity]` を定義します。追加の読み取りや権限はなく、承認済みの
匿名グラフと言語センサスから導出します。`graph` と `analyzed` では必須、`none` と
`summary` では存在しません。

評価レポートは、定義量、制御フロー、機能の範囲、依存関係の絡み合い、環境依存性、不透明性、および方言依存性という 7 つの次元を示します。結果は数値スコアではなく、範囲で示されます。`overall_score` は予約されており、値は設定されません。0〜100 の値では、サポートされていない精度を示唆してしまうためです。

各次元は対象母集団の 1 次元正確ヒストグラムを持ちます。量はサイズバンド、他の 6 次元は
件数バンドを使います。どちらも `not_applicable` と `unknown` を含み、
`eligible = assessed + not_applicable + unknown` を満たします。オブジェクト別複合値や、
種類・機能・スキーマ別のクロス集計はありません。明確に識別されたエンジン生成・補助
オブジェクトはインベントリには残りますが評価対象外です。テンポラリオブジェクトや
フラグ不明のオブジェクトは対象です。サイトにインストールされたプラグイン、CLR Assembly、Java、ライブラリは
本文を読めなくても実際の移行作業であり、明示的なエンジン生成フラグだけが除外します。

`assessment_population_complete` は対象オブジェクトがすべて既知かを示します。
`inventory_complete` とは独立し、省略は false です。不完全な母集団では、既知の下限が
すでに `very-high` でない限り全体バンドは `unknown` です。

カバレッジは次元ごとに記録します。`not_applicable` は完了した評価です。一部評価は
適用可能な次元の一部が既知で別の次元が不明、未評価は適用可能な次元が一つも既知でない
状態です。不明な証拠を低複雑度とは扱いません。一部次元は下限が `very-high` でない限り
`unknown` で、全体バンドは上下限が一致した場合だけ出力します。`graph` は定義を読まない
ため、空でない母集団に全体判定を出しません。完全な空母集団は `not-applicable` です。

ラップされたオブジェクトは、部分的な言語の調査結果が得られない場合でも、オパシティヒストグラムの`unknown`バケットに寄与します。オパシティバンドとそのカバレッジをまとめて読み取ることで、小さな観測されたバンドが、その未知の集団情報なしで読み取られることはありません。評価自体が失敗した場合、完全なインベントリが保持され、すべての情報が不明であることを示す集計値が使用されます。ラップされたり、隠されたりした定義、不完全なグラフ、不完全な要件の証拠、選択された範囲の境界、およびサポートされていない言語または方言は、明示的な制限として残ります。これらの制限に関する記述は、可能な限り、アーティファクトと調査結果の証拠から導かれます。`unsupported-dialect`は、調査結果が方言を特定し、`unavailable`を報告できるものの、`unsupported`の状態ではないため、区別されます。これは、定義が読み取られたものの、指定されたアナライザーがその方言をサポートしていないことを意味し、ソースが隠されたり、ラップされたりしたことを意味するものではありません。

そのレコードには、対象となるデータセットに含まれるアナライザーのバージョンと、分析範囲、方言、および文法プロファイルのソートされたセットが記録されています。2つのキャプチャを比較できるのは、それらのセット、契約、評価者、範囲、および対象データセットのポリシーがすべて一致する場合のみです。1つのバンドルは、各子ソースの複雑さを保持し、エンジンやアナライザー間でそれらを集計することはありません。

複雑さの評価に関する契約とアサーションのバージョンは独立しています。正確なフィールドと不変条件については、[フォーマット参照](FORMAT.md) を参照してください。

## エンジン別カバレッジ

現在のコレクタは次のファミリをモデル化します。

| エンジン | モデル化するオブジェクト・ファミリ |
|---|---|
| PostgreSQL | ビュー、マテリアライズド・ビュー、シーケンス、ルーチン、集約、enum/domain/composite/range 型、トリガー、デフォルト、チェック、ポリシー、ルール、イベント・トリガー、拡張、外部テーブル/サーバー、パブリケーション、サブスクリプション、テーブルスペース、ネイティブ関数 |
| MySQL | ビュー、ストアド関数/プロシージャ、トリガー、スケジュール・イベント、ビュー依存、FEDERATED テーブル、ロード可能 UDF 登録 |
| SQL Server | ビュー、ストアド・プロシージャ、スカラー/テーブル関数、CLR モジュール、トリガー、デフォルト、チェック、ルール、シノニム、シーケンス、ユーザー定義型、CLR Assembly、外部データ・オブジェクト、全文カタログ、パーティション・オブジェクト、PRIMARY 以外のファイルグループ、証明書、鍵、データベース・スコープ資格情報、リンク・サーバー、SQL Server Agent ジョブ |

各 Blueprint は既知の未モデル化ファミリを列挙します。`visibility`、完全性フィールド、
未収集ファミリ一覧が裏付けない限り、件数ゼロを不在の証拠にしないでください。

## 要件証拠

アーティファクトの要件は、限定されたカタログのカラムからのエンジンに関する情報、または専用のエンジン対応の構文チェックによって決定されます。一般的な字句解析では、エンジンに特化した要件は生成されません。分析された言語機能が同じ情報を反映する場合、要件が優先され、その機能は字句的な観察として残ります。要件が欠落しているからといって、すべての要件トークンがチェックされたことを証明するものではありません。

v7 graph/analyzed のすべてのオブジェクトは、`requirement_status` を `complete`、`partial`、`unavailable`、または `not_applicable` として記録します。`complete` のみ、そのオブジェクトに対する要件がゼロであることを示す空のリストを作成します。`partial` は、ある事実またはプロデューサーが、完全な網羅性なしに成功したことを記録します。`unavailable` は、どのプロデューサーも有効な網羅性を確立できなかったため、既知の要件または外部の前提条件の証拠を伴うことができないことを記録します。このような証拠には `partial` が必要です。これらはどちらも、要件に由来する複雑さの観測に寄与しますが、完全なオブジェクトは評価可能です。`not_applicable` は、要件および外部前提条件の記録を禁止します。インベントリレベルの `requirements_complete` は、エンジンバージョンとエディションのチェック、完全な評価の実施、およびすべての出力オブジェクトが完全であるか、または適用できない場合にのみ真となります。PostgreSQL、MySQL、および SQL Server は、すべての適用可能なアーティファクトカタログが試行され、選択された範囲のデータが完全であることが証明された場合にのみ、集計値を設定します。拒否されたカタログ、または読み取れないカタログ、またはそのデータが完全であることを証明できない選択範囲は、読み取られたカタログから完全なオブジェクトごとの証拠を消去することなく、集計値を偽として維持します。Oracle では、アーティファクトの要件は報告されません。

## 外部前提条件

移植可能なテーブル DDL 以外に依存するオブジェクトには匿名の外部前提クラスが付きます。

| クラス | 運用者が解決する事項 |
|---|---|
| `postgresql_extension` | 互換拡張パッケージとターゲット・バージョン |
| `postgresql_native_function` | ネイティブ・ライブラリと ABI 互換性 |
| `mysql_loadable_udf` | ロード可能 UDF バイナリとソース・サーバー ABI |
| `sqlserver_clr_assembly` | CLR 有効化、Assembly、ランタイム、信頼ポリシー |
| `foreign_endpoint` | ネットワーク、プロバイダ、リモート DB、認証 |
| `replication_topology` | パブリケーション/サブスクリプション構成とターゲット方針 |
| `physical_storage` | ファイルグループまたは物理配置設計 |
| `server_feature` | サーバー/マネージド・サービス機能の可用性 |
| `certificate_material` | ターゲット方針に従う証明書発行またはインポート |
| `encryption_or_credential_material` | 鍵、資格情報、外部キーストア、シークレット管理 |
| `sqlserver_agent` | Agent の可用性、実行環境、ジョブ統制 |

Blueprint はバイナリ、シークレット、エンドポイント実体が必要かを記録しますが、実体は
収集しません。外部オブジェクトは best-effort の省略ではなく、明示的な移行タスクにします。

## 言語機能センサス

`analyzed`の詳細情報は、`dbwarp-language-feature-census/v1`ブロックを追加します。スキーマv7は`lexical-v2`を出力し、これは実行可能または宣言的な部分のみを分析し、`analysis_span = "executable-body"`を記録します。外部の作成部分、識別子、シグネチャ、戻り値の宣言、およびモジュールのオプションは除外されます。本体を安全に分離できない場合、収集ツールは不明な範囲と利用できない証拠を記録します。定義がないオブジェクトは`not-applicable`を使用します。省略された範囲は、エンジンから推測されるのではなく、不明と解釈されます。アナライザーは、サポートされている定義に対して`status = "partial"`を報告します。これは、パーサー、コンパイラ、セマンティックバインダー、または翻訳成功の保証ではないためです。欠落している、またはサポートされていない定義の証拠は`unavailable`であり、証明された適用不可能な分析は`not_applicable`です。

定義サイズ、文数、トークン数、ネスト、循環的複雑度、不透明/動的領域を境界付き
バンドで記録します。制御フロー、結合、サブクエリ、CTE、集約、ウィンドウ、DML、
DDL、一時オブジェクト、動的 SQL、JSON、XML、空間、ベクトル、送出エラー、
トランザクション制御、ref cursors、アンカー型、interval、time zone、Boolean、LOB、セキュリティを閉じた
語彙で示します。エンジン・コンテキストには正規化文法プロファイル、MySQL SQL モード、
SQL Server の互換性、`ANSI_NULLS`、`QUOTED_IDENTIFIER` の設定が含まれます（利用可能な場合）。

字句解析器は、カウントする前にコメント、引用されたリテラル、および引用された識別子を削除します。トリガーイベント宣言、PostgreSQL `EXECUTE FUNCTION`、およびSQL Serverのモジュールオプションに関するコンテキストルールがあります。それでも、すべての結果は粗い計画の根拠となります。PL/SQL でラップされたものは拒否されます。難読化されたバイトは、決して妥当な身体測定値にはなりません。

## 推奨レビュー手順

1. 既定の `summary` レベルを成果物カタログのレビューと共に実行します。ポリシーが
   テーブルカタログだけを許可する場合は、代わりに `--artifact-detail none` を使います。
   v7 はインベントリ状態を省略せず、この判断を明示的に記録します。
2. 件数、外部クラス、可視性、読めないカタログ、未モデル化ファミリを確認します。
3. 匿名依存トポロジを許容できる場合だけ `graph` を承認します。
4. 定義の一時読み取りを許容できる場合だけ `analyzed` を承認します。
5. 監査ログはアクセス制御された証跡としてローカルに保管します。指定された受信者が
   エンドポイント、ID、パス、機能低下の詳細を必要とする場合に限り、承認済みの安全な
   チャネルで共有します。
6. インベントリに記録されたオブジェクトを自動的に再作成または変換できるとは想定せず、DBWarp に確認してください。

正確なシリアライズ済みフィールドについては、[フォーマットリファレンス](FORMAT.md)を参照してください。実行時の読み取り、書き込み、警告、信頼性に関する表明については、[監査リファレンス](AUDIT.md)を参照してください。
