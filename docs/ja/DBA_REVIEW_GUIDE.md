このガイドは、本番環境または本番相当の環境で `dbwarp-blueprint` を実行するかどうかを判断する DBA とセキュリティレビュー担当者を対象としています。

## 実行モデル

`dbwarp-blueprint` はローカルのコマンドラインバイナリです。ライブモードでは、指定した URI に対してデータベース接続を 1 本開き、ローカルの TOML ファイルを書き込みます。DBWarp インフラストラクチャ、クラウド API、テレメトリエンドポイント、ライセンスサーバー、更新サーバーには接続しません。

`--from-toml` デッキモードでは、データベースに一切接続しません。

## 推奨アカウント

カタログメタデータの読み取り権限と、Tier 2 圧縮を有効にする場合はユーザーテーブルの行をサンプリングする権限を持つ、専用の低権限アカウントを使用してください。

推奨される特性:

- 書き込み権限なし
- DDL 権限なし
- superuser/admin ロールなし
- 読み取りアクセスは評価対象のデータベースに限定
- パスワードまたはトークンは URI に埋め込まず、ファイルまたはプロンプトで提供

正確な権限付与は、エンジンと顧客ポリシーによって異なります。アカウントが一部のカタログビューを読み取れない、または一部のテーブルをサンプリングできない場合、ツールは明確に失敗するか、情報量を減らしたBlueprintを出力する必要があります。監査ログを保存してください。

バージョン対応のスクリプトと注意事項は
[`../../sql/grants/README.md`](../../sql/grants/README.md) を使用してください。承認済みの取得後は、
`sql/revoke/` の対応するスクリプトで専用コレクターアカウントを削除してください。
実行前に、正確なデータベース、ホストパターン、ロール、ログインの対象を確認してください。

## Tier 1: カタログのみ

`--measure-compression` を指定しない場合、Tier 1 が既定です。

読み取るもの:

- エンジンのバージョン
- テーブル一覧と匿名化順序の入力
- 概算行数
- テーブルとインデックスのサイズ
- 列の型ファミリー、NULL 許容性、および利用可能な場合は丸められた長さ統計
- インデックス型、一意性、および匿名化された列序数
- 利用可能な場合は外部キーグラフの形状
- `--no-rtt-probe` が設定されていない限り、任意の顧客側 RTT プローブ

行の値は読み取りません。

## 非テーブル成果物インベントリ

スキーマ v4 以降の Blueprint は、行サンプリングとは独立して非テーブルオブジェクトを収集します。既定の `--artifact-detail summary` はオブジェクトカタログを読みますが定義は読まず、有界件数と外部前提条件クラスだけを出力します。

`--artifact-detail graph --yes` は匿名オブジェクト ID と依存エッジを追加します。`--artifact-detail analyzed --yes` は利用可能な定義も一時的に読み、有界な字句機能および複雑度バンドだけを出力します。定義テキスト、ソースオブジェクト名、エンドポイント、プロバイダー文字列、プリンシパル、秘密、鍵、証明書、パッケージ名、バイナリは決してシリアライズされません。

カタログ権限は不在の主張に影響します。`visibility`、`inventory_complete`、`dependencies_complete`、`catalogs_unreadable`、`families_not_inventoried` を確認してください。これらが欠落を示す場合、件数ゼロを証拠と解釈しないでください。`DBP1410W` は読み取れなかった任意の成果物カタログを示します。

匿名依存トポロジでもアプリケーションを識別できます。このリスクを許容できる場合だけ `graph` または `analyzed` を承認してください。[`ARTIFACT_INVENTORY.md`](ARTIFACT_INVENTORY.md)を参照してください。

## Tier 2: 圧縮測定

Tier 2 は、次の明示的な組み合わせによってのみ有効になります:

```bash
--measure-compression --yes
```

Tier 2 ではさらに、制限された行サンプルをプロセスメモリへ読み込みます。サンプルバイトは内部の row-frame バッファにエンコードされ、zstd レベル 3 でローカル圧縮され、丸められた比率として要約された後、破棄されます。

サンプルバイトは:

- `blueprint.toml` に書き込まれない
- 監査ログに書き込まれない
- 一時ファイルに書き込まれない
- データベース接続以外のネットワークへ送信されない
- サンプルの要約後に保持されない

DBWarp の性能とエグレスコストは生のテーブルバイトではなく圧縮後のバイトに左右されるため、Tier 2 は有用です。

## RTT プローブ

既定では、接続確立後に 5 回の `SELECT 1` クエリを実行します。これにより、`connect_total_ms`、`query_rtt_ms_p50`、`query_rtt_ms_p95` を含む `[network]` ブロックが出力されます。

このプローブは、Blueprintツールがソースデータベースに対してどの位置で実行されたかをオペレーターが理解するためのものです。移行 WAN の RTT ではありません。

次で無効化できます:

```bash
--no-rtt-probe
```

## 読み取るファイル

実行時に、本ツールが読み取るのは、パスワードファイル、ユーザーファイル、TLS CA/証明書/鍵ファイル、Entra トークンファイル、または `--from-toml` 入力ファイルなど、コマンドラインで明示的に指定されたファイルだけです。

`~/.pgpass`、`~/.my.cnf`、クラウド資格情報ファイル、SSH 鍵、シェル履歴、既定のパスワード環境変数といった一般的な暗黙の資格情報保存場所は意図的に読み取りません。

完全な一覧については、[`../AUDIT.md`](AUDIT.md)を参照してください。

## 書き込むファイル

本ツールは、アクティブなモードで選択されたパスにだけ書き込みます:

- ライブモードの `--out` Blueprint TOML
- 要求された場合の `--deck`
- 要求された場合の `--audit-log`
- バッチモードの `--out-dir`: `bundle.toml`、`blueprints/`、`audits/`、
  所有権マーカー、および部分的な失敗を報告する必要がある場合の `errors.txt`
- すべての実行で stderr に出力される監査ログ

オペレーティングシステムの暗黙の一時ディレクトリは使用しません。
アトミックなバッチ公開では、`--out-dir` の隣にステージング用または復旧用の
ディレクトリが作成される場合があります。処理可能な失敗が発生した場合は、
そのディレクトリを削除するか、以前のバンドルを復元します。

## 出力レビューのチェックリスト

`blueprint.toml` を共有する前に、次を確認してください:

- ヘッダーが固定の `dbwarp-blueprint v6` ヘッダーである
- テーブル ID が `table-001` のような形式である
- 列 ID が `col-1` のような形式である
- スキーマ ID が `schema-A` のような形式である
- 実際のテーブル名、列名、インデックス名、スキーマ名、ユーザー名が含まれていない
- 非テーブルオブジェクト名、定義テキスト、エンドポイント文字列、資格情報、鍵/証明書素材、パッケージ名、バイナリが含まれていない
- 行の値が含まれていない
- 数値が [`../FORMAT.md`](FORMAT.md) の記載どおりに丸められている
- 任意の圧縮セクションに、比率とサンプルメタデータだけが含まれている
- 成果物完全性フィールドが、フィルターされた可視性、読み取り不能なカタログ、既知の未モデル化ファミリを開示している

既定の balanced MySQL 出力には、宣言された正確な容量とインデックス
プレフィックス長に加え、相対的に丸められた average/p95 サンプルが含まれます。3 つの
fidelity マーカーを明示的に確認してください。`--length-fidelity exact --yes` を使用した場合は、
正確なサンプル統計の共有も承認してください。それでも、行の値と実際のオブジェクト名は
含まれていてはいけません。fidelity マーカーが欠けている場合は legacy/unknown であり、
ベンチマーク対応のメタデータとして扱ってはいけません。

このマーカーは、サンプリングがすべてのテーブルを網羅したことを示すものではありません。ベンチマークの引き渡しでは、
estimator マニフェストに未サンプリングの可変幅インデックス列が 0 であることも示す必要があります。
このゲートが失敗する場合は `--max-wall-secs` を増やして再収集してください。

## 運用上の安全性

推奨される初回実行:

```bash
--sample-rows 500 --max-wall-secs 120
```

承認後に推奨される本番スタイルの実行:

```bash
--sample-rows 1000 --max-wall-secs 300
```

本番ポリシーでプライマリ上のサンプリングが禁止されている場合は、リードレプリカから実行してください。
