このガイドは、本番環境または本番相当の環境で `dbwarp-blueprint` を実行するかどうかを判断する DBA とセキュリティレビュー担当者を対象としています。

## 実行モデル

`dbwarp-blueprint` はローカルのコマンドラインバイナリです。ライブモードでは、指定した URI に対してデータベース接続を 1 本開き、ローカルの TOML ファイルを書き込みます。DBWarp インフラストラクチャ、クラウド API、テレメトリエンドポイント、ライセンスサーバー、更新サーバーには接続しません。

`--from-toml` デッキモードでは、データベースに一切接続しません。

## 推奨アカウント

カタログメタデータの読み取り権限と、Tier 2 圧縮を有効にする場合はユーザーテーブルの行をサンプリングする権限を持つ、専用の低権限アカウントを使用してください。

推奨される特性:

- 書き込み権限なし
- レビュー担当者が、DDL 操作も可能なメタデータ権限 `TRIGGER` と `EVENT` を
  使う MySQL enhanced キャプチャを明示的に承認した場合を除き、DDL 権限なし
- superuser/admin ロールなし
- 読み取りアクセスは評価対象のデータベースに限定
- パスワードまたはトークンは URI に埋め込まず、ファイルまたはプロンプトで提供

Exact grants（権限）は、エンジンやポリシーによって異なります。もしアカウントが一部のカタログビューを読み取れない、または一部のテーブルをサンプリングできない場合、ツールは明確にエラーを発生するか、制限されたBlueprintを出力します。監査ログは保持してください。

バージョン対応のスクリプトと注意事項は
[`../../sql/grants/README.md`](../../sql/grants/README.md) を使用してください。承認済みの取得後は、
`sql/revoke/` の対応するスクリプトで専用コレクターアカウントを削除してください。
実行前に、正確なデータベース、ホストパターン、ロール、ログインの対象を確認してください。

## Tier 1: メタデータのみ（行サンプリングなし）

`--measure-compression` を指定しない場合、Tier 1 が既定です。

読み取るもの:

- エンジンのバージョン
- テーブル一覧と匿名化順序の入力
- 概算行数
- テーブルとインデックスのサイズ
- 列の型ファミリー、NULL 許容性、および利用可能な場合は丸められた長さ統計
- インデックス型、一意性、および匿名化された列序数
- 利用可能な場合は外部キーグラフの形状
- データベースエンドポイントから返される、可能な範囲での粗いソース容量帯
- 既定の `--artifact-detail summary` でオブジェクトカタログから得る、非テーブル
  オブジェクトと外部前提条件の上限付き件数（定義は読まない）
- オプションのRTTプローブですが、`--no-rtt-probe`が設定されている場合は無効になります。

行の値は読み取りません。

## ソース環境

schema v7 の `[source_environment]` ブロックは、選択したデータベース接続を
通じて返された値だけから導出されます。コレクターが自身のホストを調べることも、
そのワークステーションをデータベースサーバーとして示すこともありません。

PostgreSQL と MySQL は、通常の最小限の権限下でデータベースのバッファ設定を公開しており、その結果、メモリに関する情報は一部の証拠となりますが、`database-buffer-cache` に基づいています。CPU に関する情報は不明です。

SQL Server は、`--artifact-detail graph` または `analyzed` の、より高度なモードでのみ、ソース環境の容量を要求します。ベーシックモードとスタンダードモードでは、オペレーティングシステムの容量に関するクエリは発行されず、容量範囲は `not-requested` として記録されます。

強化されたスクリプトは、必要なサーバー全体の権限 `VIEW SERVER STATE` (2019) または `VIEW SERVER PERFORMANCE STATE` (2022/2025) を、DBAが削除できる別のバッチで付与します。強化されたキャプチャがDMVを読み取れない場合、キャプチャは続行され、カタログが読み取り不可能であることを記録します。代わりに、ローカルマシンの値を使用したり、容量を勝手に設定したりすることはありません。

この取得経路は、クラウド、Kubernetes、ハイパーバイザー、オペレーティング
システムの API に接続しません。

## 非テーブル成果物インベントリ

Blueprintsは、行のサンプリングとは独立に、テーブル以外のオブジェクトを個別にインベントリします。既定の設定`--artifact-detail summary`では、オブジェクトのカタログは読み取られますが、定義は読み取られず、限られた数のカウントと、外部の依存関係クラスのみが出力されます。

`--artifact-detail graph --yes` は匿名オブジェクト ID と依存エッジを追加します。`--artifact-detail analyzed --yes` は利用可能な定義も一時的に読み、有界な字句機能および複雑度バンドだけを出力します。定義テキスト、ソースオブジェクト名、エンドポイント、プロバイダー文字列、プリンシパル、秘密、鍵、証明書、パッケージ名、バイナリは決してシリアライズされません。

カタログ権限は不在の主張に影響します。`visibility`、
`inventory_complete`、`dependencies_complete`、`requirements_complete`、
`catalogs_unreadable`、`families_not_inventoried` を確認してください。これらが
欠落を示す場合、件数ゼロや空の要件リストを証拠と解釈しないでください。
graph/analyzed の詳細度では、各オブジェクトの `requirement_status` も確認します。
空のリストがそのオブジェクトの要件ゼロを証明するのは `complete` の場合だけです。
`partial` は網羅性を主張せず既知の事実を保持し、`unavailable` は利用可能な
カバレッジが確立されなかったことを示します。どちらの場合も、そのオブジェクトの
要件から導出される結合評価は不明のままです。`DBP1410W` は読み取れなかった
任意の成果物カタログを示します。

匿名依存トポロジでもアプリケーションを識別できます。このリスクを許容できる場合だけ `graph` または `analyzed` を承認してください。[`ARTIFACT_INVENTORY.md`](ARTIFACT_INVENTORY.md)を参照してください。

## Tier 2: 圧縮測定

Tier 2 は、次の明示的な組み合わせによってのみ有効になります:

```bash
--measure-compression --yes
```

Tier 2は、さらに、限られた数の行のサンプルをプロセスメモリに読み込みます。サンプリングされたバイトは、メモリ内のバッファにエンコードされ、集計圧縮率、NULL値の密度、cardinality/frequency、長さ、およびスタイルに関する測定値を導き出すために使用されます。その後、これらの値と一時的なフィンガープリントは破棄されます。

サンプルバイトは:

- `blueprint.toml` に書き込まれない
- 監査ログに書き込まれない
- 一時ファイルに書き込まれない
- データベース接続以外のネットワークへ送信されない
- サンプルの要約後に保持されない

Tier 2は、転送時間とデータ転送コストが、圧縮されたバイト数に依存するため、価値があります。生のテーブルのバイト数ではありません。

## RTT プローブ

既定では、接続確立後に 5 回の `SELECT 1` クエリを実行します。これにより、`connect_total_ms`、`query_rtt_ms_p50`、`query_rtt_ms_p95` を含む `[network]` ブロックが出力されます。

このプローブは、Blueprintツールがソースデータベースに対してどの位置で実行されたかをオペレーターが理解するためのものです。移行 WAN の RTT ではありません。

次で無効化できます:

```bash
--no-rtt-probe
```

## 読み取るファイル

実行時に、本ツールが読み取るのは、コマンドラインで明示的に選択されたファイル、
または明示的に選択したバッチマニフェストやバンドルが参照するファイルだけです。
パスワード、ユーザー、匿名化キー、TLS CA/証明書/鍵、Entra トークン、構造化
ファイル入力、Blueprint／バンドル入力などが該当します。

`~/.pgpass`、`~/.my.cnf`、クラウド資格情報ファイル、SSH 鍵、シェル履歴、既定のパスワード環境変数といった一般的な暗黙の資格情報保存場所は意図的に読み取りません。

この記述はアプリケーションが制御する資格情報探索に関するものです。データベース、
TLS、DNS、統合認証の各ライブラリは、OS の trust store、設定、資格情報 cache を
参照する場合があります。ホストポリシーが要求する場合、これらのプラットフォーム
依存動作を別途レビューまたはトレースしてください。

完全な一覧については、[`../AUDIT.md`](AUDIT.md)を参照してください。

## 書き込むファイル

本ツールは、アクティブなモードで選択されたパスにだけ書き込みます:

- ライブモードの `--out` Blueprint TOML
- 要求された場合の `--deck`
- 要求された場合の `--audit-log`
- バッチモードの `--out-dir`: `bundle.toml`、`blueprints/`、`audits/`、
  所有権マーカー、および部分的な失敗を報告する必要がある場合の `errors.txt`
- すべての実行で stderr に出力される監査ログ

オペレーティングシステムの暗黙の一時ディレクトリは使用しません。
アトミックなバッチ公開では、`--out-dir` の隣にステージング用または復旧用の
ディレクトリが作成される場合があります。処理可能な失敗が発生した場合は、
そのディレクトリを削除するか、以前のバンドルを復元します。

## 出力レビューのチェックリスト

`blueprint.toml` を共有する前に、次を確認してください:

- ヘッダーが固定の `dbwarp-blueprint v7` ヘッダーである
- テーブル ID が `table-001` のような形式である
- 列 ID が `col-1` のような形式である
- スキーマ ID が `schema-A` のような形式である
- 実際のテーブル名、列名、インデックス名、スキーマ名、ユーザー名が含まれていない
- 非テーブルオブジェクト名、定義テキスト、エンドポイント文字列、資格情報、鍵/証明書素材、パッケージ名、バイナリが含まれていない
- 行の値が含まれていない
- 数値が [`../FORMAT.md`](FORMAT.md) に記載された exact または rounded の精度を
  使用している。exact の opt-in フィールドは、より機密性の高い情報としてレビューする
- 任意のサンプル由来セクションには、集約された圧縮、NULL 密度、カーディナリティ／
  頻度、長さ、スタイル、サンプル来歴のメタデータだけが含まれ、サンプリング値は含まれない
- 成果物完全性フィールドが、フィルターされた可視性、読み取り不能なカタログ、既知の未モデル化ファミリを開示している

既定のバランス調整されたMySQL出力には、正確に宣言された容量とインデックスのプレフィックス長、および相対的に丸められた平均値/p95サンプルが含まれます。3つの忠実度マーカーを明示的に確認してください。 `--length-fidelity exact --yes`が使用された場合は、正確なサンプリングされた統計も承認してください。行の値と実際のオブジェクト名は依然として存在してはなりません。Blueprintは忠実度マーカーなしで、古いバージョンによって生成されました。再度取得してください。

このマーカーは、サンプリングがすべてのテーブルを網羅したことを主張するものではありません。もし`DBP1406W`が報告された場合、`--max-wall-secs`を増やし、再度サンプリングを行ってください。

## 運用上の安全性

推奨される初回実行:

```bash
--sample-rows 500 --max-wall-secs 120
```

承認後に推奨される本番スタイルの実行:

```bash
--sample-rows 1000 --max-wall-secs 300
```

本番ポリシーでプライマリ上のサンプリングが禁止されている場合は、リードレプリカから実行してください。
