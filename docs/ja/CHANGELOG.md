## 1.5.1

### 取得と忠実度

- Blueprint スキーマ v6 を維持し、カタログ推定値、サンプリングで得られた観測値、
  および取得できない統計鮮度の証拠を区別します。
- バイナリペイロードの測定、圧縮済みペイロードの特性把握、上限付き圧縮プローブを改善します。
  異なる `sample_encoding` の値に基づく比率には互換性がありません。
  利用側は測定値を使用する前に、そのエンコーディングを認識できなければなりません。
- MySQL と SQL Server の適応的サンプリング再試行に上限を設け、過大な値や文字セット変換による
  サイズ増加にも対応します。残る接頭辞バイアスを記録し、元のサンプリング値の長さメタデータを保持します。
- 接続の文字セットによって返されるバイト長が変わる場合の、MySQL の切り詰め検出を修正します。
- 共有 Blueprint コアで、合成値の長さ、カーディナリティ、分布、局所性の扱いを改善します。

### 運用とレビュー

- 専用の最小権限アカウントの設定、ソースからのビルド手順、比較ビルドの検証、
  検証済みデータベースバージョン一覧を明確にします。
- 機械翻訳文書と実行時の表現を更新し、引き続き英語を正本、翻訳を補足資料とします。
- 公開ソースの実行可能ファイル権限とリリースアーカイブの検査を強化します。
- ソースおよびバイナリ配布物に、リリース履歴、サポート、貢献方法のガイドを追加します。
- 対応するバナーモードを変えずに、未使用の ASCII アートを削除します。

### 互換性と導入

既存の Blueprint は新しいコレクターで引き続き読み取れます。逆方向は保証されません。
1.5.0 のリーダーは新しい任意フィールド `sample_layout` を拒否し、古い利用側も
新しい圧縮サンプルのエンコーディングを拒否する場合があります。
したがって、スキーマ v6 のパーサーであることだけでは、前方互換性の証拠になりません。
新しい取得結果をプレゼンテーション、合成生成、または圧縮に基づく計画に使用する前に、
利用側のツールをコレクターと合わせて更新し、検証してください。

正確なリリース成果物とチェックサムを固定してください。以前のリリースの検証は、
異なるバイナリが同一の結果を生成する証拠にはなりません。
