## 1.6.0

### Blueprint schema v7

- 明示的なテーブル分類、ストレージ構成、パーティション、セグメント状態、
  列の順序、および型、NULL 許容性、生成値、ID に関するより詳細な意味を
  含む schema v7 を出力します。
- 構造、行数、割り当て済みバイト、統計、ソース環境の観測について、
  テーブル単位および取得全体の証拠を追加します。欠落、拒否、不正、または
  選択範囲により制限された証拠は、測定済みゼロや完全なインベントリとして
  表すのではなく、明示的に残します。
- カタログに基づくオブジェクト単位の要件状態と、上限付きの複雑性証拠を
  アーティファクトインベントリに追加します。必要なカタログまたは選択した
  評価対象の完全性を証明できない場合、集約された完全性は false のままです。
- schema-v1からschema-v6までの入力形式との互換性を維持してください。古いバージョンでは、schema-v7形式のファイルが読み込めない場合があります。
### 取得の忠実度と安全性

- PostgreSQL、MySQL、SQL Server で、完全な上限付き読み取り、部分サンプル、
  カタログ推定を区別します。行セキュリティと継承の境界、適応型 MySQL
  レンジウィンドウ、SQL Server のメモリ最適化テーブルも対象です。
- 丸められた証拠や不完全な証拠が正確な主張にならないよう、カーディナリティ、
  NULL 数、パーティション、リレーション、集約の整合性を強化します。
- PolyBase がインストールされていない場合、SQL Server 外部テーブルの対応範囲を
  明示的な制限として報告します。
- 行、バイト、値、期限の上限内で取得します。非致命的な劣化は、安定した
  メッセージコードとともに Blueprint と監査に表示されます。

### Oracle のスコープ境界

- Oracle Basic カタログの取得機能を、Oracle 12c、19c、21c および
  23ai/26ai に対してプレビュー版として追加しました。これは、確認後に利用可能になり、
  カタログ情報のみを取得し、テーブルの行データは読み込みません。制限事項については、
  `sql/grants/ORACLE_PREVIEW.md` を参照してください。

### リリース成果物と認証

- Linux リリースアーカイブには、SQL Server の Kerberos/GSSAPI 認証が
  含まれます。統合認証を選択した場合にのみプラットフォームの Kerberos
  ランタイムを読み込むため、コレクターは Kerberos ライブラリなしで起動します。
  ランタイムがない場合は、統合認証に限って `DBP1604E` を報告します。
  Windows リリースバイナリには、引き続き SQL Server の SSPI 認証が含まれます。
- どちらの統合認証方式もオペレーティングシステムの資格情報を使用し、
  サーバープリンシパルが想定した値と一致しない場合は接続を拒否します。

### 運用と互換性

- SQL Server の Enhanced 権限付与スクリプトは、別のバッチでサーバーレベルの
  権限を 1 つ追加します。SQL Server 2019 では `VIEW SERVER STATE`、2022 および
  2025 では `VIEW SERVER PERFORMANCE STATE` です。これにより、
  `--artifact-detail graph` または `analyzed` を指定した Enhanced 取得で、
  自己管理サーバーの大まかな CPU とメモリの範囲を報告できます。Basic と
  Standard はこの権限を付与せず、これらの範囲を不明として報告します。DBA は
  このバッチを削除して、権限なしで Enhanced を維持できます。
- SQL Server、PostgreSQL、Parquet、および Windows 認証の依存関係を、公開済みの
  セキュリティアドバイザリを修正するリリースに更新します。SQL Server ドライバーは
  0.13 に移行します。`--tls-ca` は制限的な意味を維持し、指定された CA だけを
  信頼します。`--max-wall-secs` は取得全体に対する唯一の期限のままです。
- SQL Server は、テーブル以外のオブジェクトの分析が要求された場合にのみ、
  オペレーティングシステムの容量を読み取ります（`--artifact-detail graph` または
  `analyzed`）。その他の取得では、読み取り失敗ではなく、容量範囲が未要求であると
  記録します。
- 英語のドキュメントが引き続き正本です。翻訳版 Markdown は補助資料であり、
補足情報が含まれており、独自の翻訳に関する注意書きが付いています。

### プレゼンテーション

- プレゼンテーションに、テーブル以外のオブジェクトのスライドと、独立した
  アーティファクトの複雑度スライドを追加します。複雑度スライドは複雑度が取得された
  場合にのみ表示され、各レベルの横にカバレッジを示すため、不完全な証拠が低い
  複雑度として表示されることはありません。

## 1.5.1

### 取得と忠実度

- Blueprint スキーマ v6 を維持し、カタログ推定値、サンプリングで得られた観測値、
  および取得できない統計鮮度の証拠を区別します。
- バイナリペイロードの測定、圧縮済みペイロードの特性把握、上限付き圧縮プローブを改善します。
限られた範囲での圧縮テスト。異なる`sample_encoding`の値からの比率は互換性がないため、比較する前にエンコーディングを確認してください。
- MySQL と SQL Server の適応的サンプリング再試行に上限を設け、過大な値や文字セット変換による
  サイズ増加にも対応します。残る接頭辞バイアスを記録し、元のサンプリング値の長さメタデータを保持します。
- 接続の文字セットによって返されるバイト長が変わる場合の、MySQL の切り詰め検出を修正します。

### 運用とレビュー

- 専用の最小権限アカウントの設定、ソースからのビルド手順、比較ビルドの検証、
比較ビルドの検証と、サポートされているデータベースのバージョン。
- 機械翻訳文書と実行時の表現を更新し、引き続き英語を正本、翻訳を補足資料とします。
- ソースおよびバイナリ配布物に、リリース履歴、サポート、貢献方法のガイドを追加します。
### 互換性。

既存のBlueprintは、新しいコレクターによって引き続き読み取ることができます。ただし、その逆は保証されません。1.5.0のリーダーは、新しいオプションの`sample_layout`フィールドを拒否し、古いバージョンでは、新しい圧縮サンプルエンコーディングが拒否される可能性があります。ファイルを作成する際と、それからデッキを構築する際に、同じバージョンを使用してください。

正確なリリース版のアーティファクトとチェックサムを固定してください。あるリリース版からの結果が、別のリリース版と一致することを保証するものではありません。
